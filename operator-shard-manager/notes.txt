The Core Mechanism:
Pod Discovery & Indexing: 
The controller discovers operator pods (from Deployments/StatefulSets/DaemonSets) and assigns each an index (0, 1, 2, ...). It maintains stable indices during scaling by preserving pod positions.

Consistent Hashing: Instead of simple modulo hashing, it uses a consistent hash ring (with xxhash algorithm) that ensures when you scale from N to N+1 shards, only ~1/(N+1) of resources move, not all of them.

Resource Labeling: Every target resource gets labeled with its shard index:
shard.operator.k8s.appscode.com/kubedb: "2"
The hash is computed from namespace/name or a custom JSONPath field

Operator Integration: Operators filter resources by shard label - either using label selectors (memory efficient) or predicates (allows accessing cross-shard references).

Dynamic Watching: The controller automatically discovers and watches ANY resource type specified in the ShardConfiguration, making it work with any API group.
